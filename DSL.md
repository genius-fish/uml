# `genius-uml` DSL Reference

This document describes the public DSL exposed by `genius-uml`'s `core`
module, plus the `render` module's runtime façade. It is the canonical
reference: every helper that appears here is a stable part of the API,
and helpers that don't appear here are package-private implementation
detail.

The DSL is **context-function-driven** and **typed**. A diagram is built
inside a `block { ... }` body that produces a `PUmlNode` AST value. Each
helper requires its structural context (e.g. `InArchimate`, `InSequence`)
to be in scope, so misplaced calls — `shape(...)` outside an
`archimateDiagram { ... }` — fail at compile time, not at render time.

## Concepts

A diagram passes through three layers:

```
DSL helpers (context functions)  →  PUmlNode AST  →  PlantUML source
                          block { uml { ... } }       Emit.emit
```

- **`PUmlCtx`** — a per-block mutable buffer that DSL helpers append to.
  You never construct or pass one around explicitly; it lives in the
  context-function scope.
- **`PUmlNode`** — the rendered AST. Five constructors:
  - `Statement(value: String)` — a literal line.
  - `Sequence(children: Vector[PUmlNode])` — flat siblings.
  - `Block(header: String, body: PUmlNode)` — `header { body }`.
  - `Diagram(kind: String, body: PUmlNode)` — `@startKIND ... @endKIND`.
  - `Comment(text: String)` — `' text`.
- **`Emit.emit(node: PUmlNode): String`** — pure, total fold; this is
  the only renderer-free way to inspect a diagram's source.
- **Markers** — sealed trait capabilities (`InUml`, `InArchimate`, ...)
  injected by the parent block and required by domain helpers. The
  compiler enforces nesting via missing-given errors.
- **`Alias`** — an opaque, alphanumeric-only PlantUML identifier.
  Auto-generated by helpers like `shape` and `actor`; rarely constructed
  by hand.

A diagram is fully *value*-shaped: pure code in, `PUmlNode` out, no
side-effects, safe to compose, log, snapshot, or reuse.

Almost every diagram needs:

```scala
import fish.genius.uml.dsl.*                  // block, uml, primitives, skin, Alias

import fish.genius.uml.render.{Emit, PUmlEngine, Renderer, PUmlViewer, PUmlError}
```

```scala
import fish.genius.uml.testkit.{Golden, PUmlAssertions}
import fish.genius.uml.testkit.PUmlAssertions.*
```

## Quick start

```scala
import fish.genius.uml.dsl.*
import fish.genius.uml.dsl.archimate.*
import fish.genius.uml.dsl.archimate.ShapeType.*
import fish.genius.uml.render.Emit

given ArchimateConfiguration = ArchimateConfiguration()

val doc = block:
  uml:
    archimateDiagram:
      val customer = shape(BusinessActor, label("Customer"))
      val store    = shape(ApplicationComponent, label("Web store"))
      relationship(RelationshipType.Serving)(store)(customer)

println(Emit.emit(doc))
```

Outputs (abridged):

```
@startuml
!define TECHN_FONT_SIZE 12
...
rectangle #BUSINESS "Customer" <<$archimate/business-actor>> as a0
rectangle #APPLICATION "Web store" <<$archimate/application-component>> as a1
a1 -- a0 : ""
@enduml
```

## Top-level entry points

### `block(body): PUmlNode`

Allocates a fresh `PUmlCtx` and runs `body`. Returns the produced AST.
This is the *only* user-facing entry point that allocates a top-level
context — every other helper that captures a sub-tree
(`childBlock`, `expressionWithBody`, `archimateDiagram`, etc.) inherits
counters from its surrounding `PUmlCtx`, which keeps auto-generated
aliases unique across nested scopes.

```scala
val doc: PUmlNode = block:
  uml:
    statement("Alice -> Bob: hi")
```

### `uml(body): Unit` *(requires `PUmlCtx`)*

Wraps `body` in `@startuml ... @enduml`. Injects `InUml` into the body so
domain DSLs (`archimateDiagram`, `sequenceDiagram`, `activityDiagram`)
become callable.

### `diagram(kind: String)(body): Unit` *(requires `PUmlCtx`)*

Same as `uml` but with a custom kind, so you can author non-UML PlantUML
diagrams (`gantt`, `mindmap`, `wbs`, `salt`, …):

```scala
block:
  diagram("gantt"):
    statement("[Design]    lasts 2 weeks")
    statement("[Develop]   lasts 6 weeks and starts at [Design]'s end")
```

## Primitives

All primitives live in `fish.genius.uml.dsl` and require `PUmlCtx`. They
are intentionally low-level — domain helpers compose them.

| Helper | Effect |
|---|---|
| `statement(value: String)` | Emit a single literal line. |
| `statements(text: String)` | Emit each non-empty line of `text` as its own statement. |
| `comment(text: String)` | Emit `' text` (PlantUML's single-line comment). |
| `expression(build: Alias => String): Alias` | Allocate a fresh alias, build a line from it, emit, return the alias. |
| `expressionWithBody(build: Alias => String)(body): Alias` | Like `expression`, but the built line becomes the header of a `Block` whose body is `body`. |
| `headerBlock(header: String)(body)` | Emit `header { body }` without allocating an alias. |
| `when(cond: Boolean)(body)` | Sugar for `if cond then body`. |

`emit(node: PUmlNode)` is the lowest-level escape hatch: it appends the
node verbatim. Prefer typed helpers when one exists.

## Aliases

`Alias` is an opaque type wrapping a sanitised, lower-case alphanumeric
identifier safe to splice into PlantUML source. Three constructors:

| Constructor | Purpose |
|---|---|
| `Alias.fresh(using PUmlCtx)` | Auto-allocate a unique alias from the context's `Counters`. |
| `Alias(raw: String)` | Sanitise an arbitrary string (strip non-alnum, lowercase, replace digits with English words). |
| `Alias.unsafe(value: String)` | Wrap a string verbatim (caller's responsibility). |

You'll mostly receive aliases by *consuming* helpers — `shape(...)`,
`actor(...)`, `participant(...)`, `boundary(...)` all return their newly
allocated alias. Use them as references in subsequent calls:

```scala
val customer = shape(BusinessActor, label("Customer"))
val store    = shape(ApplicationComponent, label("Web store"))
relationship(RelationshipType.Serving)(store)(customer)
```

`Alias.value` extracts the underlying `String`.

Auto-allocated aliases are globally unique across nested scopes within a
single `block { ... }` invocation: the `PUmlCtx` shares its counter with
every `childBlock` it spawns. You will not see two `as a0` lines in the
same diagram unless you mint them yourself with `Alias.unsafe`.

## Markers (compile-time capabilities)

Each marker is a sealed trait introduced as a `given` by its enclosing
helper and required as a `using` by the helpers that depend on it:

| Marker | Introduced by | Required by |
|---|---|---|
| `InUml` | `uml`, `diagram` | every domain entry-point |
| `InArchimate` | `archimateDiagram` | `shape`, `boundary`, `relationship`, `defineStereoType`, `legend`, `archimateSkinParam`, `archimatePreamble` |
| `InBoundary` | `boundary` body | (informational; no helpers gate on it currently) |
| `InSequence` | `sequenceDiagram` | every participant constructor, `step`, `box`, `autonumber`, `teozRenderingEngine`, all group helpers |
| `InBox` | `box` body | (informational) |
| `InGroup` | (reserved) | — |
| `InActivity` | `activityDiagram` | `title`, `start`, `action`, `stop`, `end`, `note` |

Misplaced calls produce a *missing given* error like:

```
no given instance of type fish.genius.uml.dsl.markers.InArchimate was found
```

That is the entire enforcement model — there is no runtime check.

## Skinparams and SVG sprites

### `skinParam(stereotype: String, properties: SkinParamProperty*): Unit` *(requires `InUml`)*

Emits `skinparam <stereotype> { <props> }`. With no properties, it emits
nothing.

```scala
import fish.genius.uml.dsl.SkinParamProperty.*

skinParam(
  "Activity",
  FontColor("black"),
  BorderColor("steelblue"),
  BorderThickness(2),
)
```

### `SkinParamProperty`

Typed enum covering the most common PlantUML skinparam values. Each case
knows its property name, its value rendering, and (for style enums) the
single canonical key it maps to.

| Cases | Rendered name |
|---|---|
| `FontColor`, `BorderColor`, `BackgroundColor`, `Color` | (same as case) |
| `FontSize`, `StereotypeFontSize`, `BorderThickness` | (same as case) |
| `Shadowing(true/false)` | `Shadowing` |
| `BorderDashed`, `BorderDotted`, `BorderPlain`, `BorderBold` | `BorderStyle` |
| `StereoTypeAlignmentRight`, `…Left`, `…Center` | `StereotypeAlignment` |
| `RoundCorner(int)`, `DiagonalCorner(int)` | (same as case) |
| `EntrySeparatorColor(hex)` | `EntrySeparator` |
| `SkinProp(name, value)` | `name` (escape hatch) |

`SkinProp` exists for properties not yet modelled — supply the literal
PlantUML name and value and you're done.

### `svgIcon(svg, name = None, description = None): SvgIcon` *(requires `InUml`)*

Registers a `<svg>` sprite under an alias and returns an `SvgIcon`
handle. Use the handle inside `legend(tags = ...)` and `ShapeLabel(tags
= ...)`. If `name` is omitted a fresh alias is allocated.

```scala
val api = svgIcon("<svg>...</svg>", name = Some("api"), description = Some("Has an API"))
```

Emits: `sprite $api <svg>...</svg>`.

## Archimate DSL

### Configuration

```scala
final case class ArchimateConfiguration(
  technicalFontSize: Int = 12,
  descriptionFontSize: Int = 10
)
object ArchimateConfiguration:
  given default: ArchimateConfiguration = ArchimateConfiguration()
```

A given `ArchimateConfiguration` must be in scope when you call
`archimateDiagram`. The default is provided automatically; override it
to tune label-line font sizes.

### Entry point

```scala
def archimateDiagram(
  body: (PUmlCtx, InArchimate, ArchimateConfiguration) ?=> Unit
)(using PUmlCtx, InUml, ArchimateConfiguration): Unit
```

Emits the canonical Archimate skinparam preamble (rounded corners,
diagonal corners, default text alignment, …) and runs `body` with
`InArchimate` in scope. Named `archimateDiagram` (rather than
`archimate`) to avoid colliding with the surrounding
`fish.genius.uml.dsl.archimate` package.

### Shapes

```scala
def shape(
  shapeType: ShapeType,
  label: ShapeLabel,
  color: ShapeColor = ShapeColor(),
  stereoType: Option[ShapeStereoType] = None
): Alias
```

Emits one `rectangle <fill> "<label>" <<archimate/...>> as <alias>`
line. Mass-objects (`ApplicationDataObject`, `BusinessObject`,
`BusinessContract`, `BusinessRepresentation`, `TechnologyArtifact`,
`PhysicalMaterial`) automatically get a `----\n ` prefix in their label
to render the Archimate top-edge separator.

### `ShapeLabel`

```scala
final case class ShapeLabel(
  name: String,
  componentType: Option[String] = None,
  componentTypeDetails: Option[String] = None,
  description: Option[String] = None,
  tags: List[SvgIcon] = Nil,
)(using config: ArchimateConfiguration)
```

The composite caption rendered inside a shape:

```
<name>
<size:tech>[<componentType>: <componentTypeDetails>]</size>

 <size:desc><description></size>

<icon0><icon1>…
```

Use the `label(...)` helper as a shorter alternative to constructing
the case class directly:

```scala
val l = label(
  "Order management",
  componentType = Some("IT system"),
  description   = Some("primary OMS"),
)
```

### `ShapeColor` and `color`

```scala
final case class ShapeColor(hex: Option[String] = None)
def color(hex: String): ShapeColor
```

`color("FF0000")` and `color("#FF0000")` are equivalent. Default is to
fall back to the layer's group default colour.

### `ShapeType` (the catalogue)

61 cases across 7 layers. Each declares its layer, its sprite-pack name,
and (via `decorate`) any label adjustments. All cases:

| Layer | Cases |
|---|---|
| **Application** | `ApplicationComponent`, `ApplicationService`, `ApplicationCollaboration`, `ApplicationInterface`, `ApplicationFunction`, `ApplicationInteraction`, `ApplicationProcess`, `ApplicationEvent`, `ApplicationDataObject` |
| **Strategy** | `StrategyResource`, `StrategyCapability`, `StrategyValueStream`, `StrategyCourseOfAction` |
| **Business** | `BusinessActor`, `BusinessRole`, `BusinessCollaboration`, `BusinessInterface`, `BusinessProcess`, `BusinessFunction`, `BusinessInteraction`, `BusinessEvent`, `BusinessService`, `BusinessObject`, `BusinessContract`, `BusinessRepresentation`, `BusinessProduct`, `BusinessLocation` |
| **Technology** | `TechnologyNode`, `TechnologyDevice`, `TechnologySystemSoftware`, `TechnologyCollaboration`, `TechnologyInterface`, `TechnologyPath`, `TechnologyCommunicationNetwork`, `TechnologyFunction`, `TechnologyProcess`, `TechnologyInteraction`, `TechnologyEvent`, `TechnologyService`, `TechnologyArtifact` |
| **Physical** | `PhysicalFacility`, `PhysicalEquipment`, `PhysicalDistributionNetwork`, `PhysicalMaterial` |
| **Motivation** | `MotivationStakeholder`, `MotivationDriver`, `MotivationAssessment`, `MotivationGoal`, `MotivationOutcome`, `MotivationPrinciple`, `MotivationRequirement`, `MotivationConstraint`, `MotivationMeaning`, `MotivationValue` |
| **Implementation** | `ImplementationWorkPackage`, `ImplementationDeliverable`, `ImplementationPlateau`, `ImplementationEvent`, `ImplementationGap` |

Static accessors:

- `ShapeType.application` / `.strategy` / `.business` / `.technology` /
  `.physical` / `.motivation` / `.implementation` — per-layer lists.
- `ShapeType.*` — flat list of all 61.

### `ShapeGroup` (layers)

`Application`, `Strategy`, `Business`, `Technology`, `Physical`,
`Motivation`, `Implementation`. Each declares its `defaultColor` (e.g.
`#APPLICATION`) and sprite-pack `prefix` (e.g. `application`).

### Boundaries

```scala
def boundary(
  label: String,
  boundaryType: Option[String] = None,
  shapeType: Option[ShapeType] = None,
  color: ShapeColor = ShapeColor(),
  stereoType: Option[ShapeStereoType] = None,
)(body: (PUmlCtx, InArchimate, InBoundary, ArchimateConfiguration) ?=> Unit): Alias
```

Emits a `rectangle "==<label>" <<...>> as <alias> { ... }` block.
Boundaries can nest. The body sees `InArchimate` so all archimate
helpers remain available; `InBoundary` is also injected in case you
want to gate further helpers on it.

### Stereotypes

```scala
def defineStereoType(
  name: String,
  description: Option[String],
  legendColor: Option[String],
  skinParameters: SkinParamProperty*
): ShapeStereoType
```

Registers a stereotype, emits the matching `skinparam rectangle<<NAME>>`
block, and returns a handle you pass to `shape(..., stereoType = ...)`
or `legend(stereoTypes = ...)`. The stereotype name is uppercased.

### Legends

```scala
def legend(
  title: String = "Legend",
  backgroundColorHexOrName: String = "#GhostWhite",
  stereoTypes: List[ShapeStereoType] = Nil,
  tags: List[SvgIcon] = Nil,
): Unit
```

Emits a `legend bottom right ... endlegend` block, including a header
row, one row per stereotype, and one row per SVG-icon tag.

### Relationships

```scala
def relationship(
  ofType: RelationshipType,
  edge: Edge = Edge.NoDirection,
  label: Option[String] = None,
): Alias => Alias => Unit
```

Curried so a relationship template can be applied to many `(source,
target)` pairs:

```scala
val composes = relationship(RelationshipType.Composition, Edge.Down, Some("composes"))
composes(parent)(childA)
composes(parent)(childB)
```

### `RelationshipType` (15 cases)

Each declares the PlantUML connector tokens that surround the `Edge`
direction:

| Type | Connector |
|---|---|
| `Composition` | `*-...-` |
| `Aggregation` | `o-...-` |
| `Assignment` | `@@-...->>` |
| `Serving` | `-...->` |
| `Flow` | `....>>` |
| `Specialization` | `-...-|>` |
| `Association` | `=...=` |
| `DirectedAssociation` | `=...=>` |
| `Realization` | `~...~|>` |
| `Triggering` | `-...->>` |
| `Access` | `~...~` |
| `ReadAccess` | `<-...~` |
| `WriteAccess` | `~...->` |
| `ReadWriteAccess` | `<~...~>` |
| `Influence` | `....>` |

`RelationshipType.*` is the flat list.

### `Edge` (5 directions)

`NoDirection` (empty), `Up`, `Down`, `Left`, `Right`. Renders into the
middle of a relationship's connector token (e.g. `*-DOWN-`).

### Helpers

- `archimateSkinParam(stereotype, props*)` — typed shortcut equivalent to
  `skinParam`, but reusable from inside an `archimateDiagram` body
  without re-summoning `InUml`.
- `archimatePreamble` — the full canonical preamble, exposed in case you
  want to call it again after a custom theme.

## Sequence diagram DSL

### Entry point

```scala
def sequenceDiagram(body: (PUmlCtx, InSequence) ?=> Unit)(using PUmlCtx, InUml): Unit
```

### Pragmas

| Helper | Emits |
|---|---|
| `autonumber()` | `autonumber` |
| `teozRenderingEngine()` | `!pragma teoz true` |

### Participants

All eight participant constructors share the signature
`(title: String, color: Option[String] = None): Alias`:

| Helper | Plant UML type |
|---|---|
| `actor` | `actor` |
| `boundary` | `boundary` |
| `control` | `control` |
| `entity` | `entity` |
| `database` | `database` |
| `collections` | `collections` |
| `queue` | `queue` |
| `participant` | `participant` |

Pass a colour as `Some("#1234AB")` to tint a single participant. The
underlying helper `participantOf(participantType, title, color)` is also
public if you need a custom PlantUML participant type.

### Boxes

```scala
def box[A](
  title: String,
  color: Option[String] = None
)(body: (PUmlCtx, InSequence, InBox) ?=> A): A
```

Emits `box "<title>" <color>` ... `end box` (no braces — PlantUML
rejects brace-delimited boxes). Returns the body's value, so you can
capture participant aliases declared inside:

```scala
val (browser, api) = box("Front-end", Some("#DAEEFF")):
  (participant("Browser"), participant("API"))
```

### Steps

```scala
def step(title: String)(from: Alias)(to: Alias): Unit
```

Emits `<from>-><to>: <title>`. Quotes and newlines in the title are
escaped (`"` is stripped, `\n` becomes `\\n`).

### Control structures

| Helper | Emits |
|---|---|
| `altGroup(title)` | `alt <title>` |
| `elseGroup(title)` | `else <title>` |
| `loopGroup(title)` | `loop <title>` |
| `optGroup(title)` | `opt <title>` |
| `parGroup(title)` | `par <title>` |
| `breakGroup(title)` | `break <title>` |
| `criticalGroup(title)` | `critical <title>` |
| `group(title)` | `group <title>` |
| `endGroup()` | `end` |

All eight openers take `Option[String] = None`. There is no
auto-closing — pair every opener with `endGroup()` exactly as in
PlantUML. Misnesting produces a malformed diagram, not a compile error.

### Example

```scala
sequenceDiagram:
  autonumber()
  val user = actor("User")
  val (browser, api) = box("Front-end", Some("#DAEEFF")):
    (participant("Browser"), participant("API"))

  step("Open store")(user)(browser)
  step("Click checkout")(browser)(api)
  loopGroup(Some("for each item"))
  step("Reserve inventory")(api)(browser)
  endGroup()
```

## Rendering

### `Emit.emit(node: PUmlNode): String`

Pure source-level renderer. Use this when you want to inspect, hash,
golden-test, or pipe the PlantUML source somewhere else without invoking
the actual rendering engine.

### `PUmlEngine` (ZIO 2 service)

```scala
trait PUmlEngine:
  def render(doc: PUmlNode, filename: String, format: FileFormat): ZIO[Scope, PUmlError, os.Path]
  def renderBytes(doc: PUmlNode, format: FileFormat): ZIO[Any, PUmlError, Array[Byte]]
```

Two layers:

- `PUmlEngine.live` — wraps PlantUML's `SourceStringReader.outputImage`.
  The output file lives inside a `Scope`-managed temp workspace and is
  deleted when the scope closes.
- `PUmlEngine.test` — captures the `.puml` source to a scoped temp dir
  with a placeholder for the requested format. Useful for unit tests
  that don't want to drag the renderer in.

`liveWith(config: PUmlConfig)` swaps in a custom config (the only
current setting is `workspaceRoot`).

### Accessor methods on `PUmlEngine`

Convenience wrappers for the canonical formats:

- `PUmlEngine.renderSvg(doc, filename = "diagram")`
- `.renderPng(...)`
- `.renderEps(...)`
- `.renderLatex(...)` — emits LaTeX without preamble
- `.renderLatexFull(...)` — emits LaTeX with full preamble

### `Renderer` (façade)

A typed top-level façade mirroring the original `fish.genius.uml.Renderer`
shape:

```scala
import fish.genius.uml.render.Renderer

ZIO.scoped(Renderer.svg(doc))     // also: .png, .eps, .latex, .latexFull, .render(format)
```

Plus extension methods on `PUmlNode`:

```scala
doc.renderedAsSvg()
doc.renderedAsPng()
doc.renderedAsEps()
doc.renderedAsLatex()
```

### `PUmlError`

```scala
enum PUmlError extends Throwable:
  case RenderFailed(cause: Throwable)
  case ViewerFailed(cause: Throwable)
  case Internal(cause: Throwable)
```

### `PUmlViewer.open(file: os.Path)`

Opens a rendered file with the OS's default viewer (`xdg-open` on Linux,
`open` on macOS, `explorer` on Windows). Useful for example apps and
side-by-side eyeballing during development.

### Example

```scala
val program: ZIO[PUmlEngine, PUmlError, Array[Byte]] =
  PUmlEngine.renderBytes(doc, FileFormat.SVG)

val live = program.provide(PUmlEngine.live)
```

## Testing helpers

### `Golden.assertMatches`

```scala
def assertMatches(
  id: String,
  actual: String,
  resourcesDir: os.Path,
  extension: String = "puml",
  update: Boolean = shouldUpdate,
): ZIO[Any, IOException, TestResult]
```

Compare `actual` to `<resourcesDir>/golden/<id>.<extension>`. When
`update` is true (or `ZIO_TEST_UPDATE_GOLDEN` is set in the env), the
file is created/overwritten and the assertion passes vacuously. When
the file is missing and `update` is false, the test fails with a hint
to set the env var.

`Golden.moduleResources("core")` resolves to
`<workspace>/core/test/resources` (uses `MILL_WORKSPACE_ROOT` if set,
otherwise `os.pwd`).

### `PUmlAssertions`

Two flavours, both imported from `PUmlAssertions.*`:

**Assertion combinators** (for the classic `assert(value)(assertion)`
pattern):

- `containsStatement(needle)`
- `containsBlock(headerNeedle)`
- `statementCountIs(needle, expected)`
- `hasDiagramKind(kind)`

**Extension methods on `PUmlNode`** (for `assertTrue`):

- `n.countStatement(needle: String): Int`
- `n.hasBlock(headerNeedle: String): Boolean`
- `n.statements: List[String]`
- `n.statementsContaining(needle: String): List[String]`
- `n.diagramKinds: List[String]`

Example:

```scala
import fish.genius.uml.testkit.PUmlAssertions.*

assertTrue(
  doc.countStatement("Alice") == 2,
  doc.hasBlock("rectangle"),
  doc.diagramKinds == List("uml"),
)
```

## Patterns and tips

### Capture aliases out of nested blocks

`block { ... }`, `boundary { ... }`, `box { ... }`, and
`expressionWithBody` all return values. Use them to lift aliases out of
the body:

```scala
val (browser, api) = box("Front-end"):
  (participant("Browser"), participant("API"))
```

### Reuse a relationship template

`relationship(ofType, edge, label)` is curried. Build it once, apply
many times:

```scala
val composes = relationship(RelationshipType.Composition)
composes(parent)(childA)
composes(parent)(childB)
composes(parent)(childC)
```

### Skip the renderer in tests

For round-trip tests, skip `PUmlEngine.live` and assert on the AST
directly with `PUmlAssertions`, or compare `Emit.emit(doc)` against a
checked-in golden via `Golden.assertMatches`. Both are pure and fast.

## Scenes: ArchiMate in 3D

The `scene` module (`genius-uml-scene`) lays an ArchiMate graph out as a 3D scene and
ships the Blender builder that builds it. It depends on `core` for `ShapeType` and
`RelationshipType`; `core` itself stays dependency-free.

```scala
import fish.genius.uml.dsl.archimate.RelationshipType.*
import fish.genius.uml.dsl.archimate.ShapeType.*
import fish.genius.uml.scene.*
import zio.json.*

val graph = SceneGraph(
  "Order handling",
  List(
    SceneNode(SceneId("customer"), NodeKind.Element(BusinessActor), "Customer"),
    SceneNode(SceneId("process"), NodeKind.Element(BusinessProcess), "Handle Order"),
    SceneNode(SceneId("system"), NodeKind.Element(ApplicationComponent), "Order System",
      children = List(SceneNode(SceneId("api"), NodeKind.Element(ApplicationComponent), "Order API"))),
  ),
  List(SceneEdge(SceneId("assigned"), SceneId("customer"), SceneId("process"), Assignment)),
)

val json: Either[SceneError, String] = SceneLayout.layout(graph).map(_.toJsonPretty)
```

```bash
blender -b -P archimate3d_blender.py -- --view scene.json --blend scene.blend --render scene.png
```

`SceneBuilder.blenderScript` returns the builder from the jar; `SceneBuilder.threeJs` the
same shapes in three.js for a browser preview. Both answer `Either[BuilderError, String]`.

### The graph

- `SceneNode(id, kind, label, children)`: `kind` is `NodeKind.Element(shapeType)`,
  `Grouping`, `AndJunction` or `OrJunction`. A node's `children` stand on its plinth:
  nesting is the caller's to decide, as a 2D diagram draws it as a boundary.
- `SceneEdge(id, source, target, relationship)`: a connector to a node's own ancestor is
  left out, since it cannot be drawn on the plinth the node stands on.
- `SceneFlow(id, name, steps)`: a walk through the graph in order, such as the
  interactions of a sequence diagram. Each `SceneStep(source, target, label)` goes from
  one node to another and says what passes between them. The layout passes flows
  through, naming per step the connector that joins its two ends (either way round),
  if there is one; the builder flies its camera along a flow (below).
- `SceneLayout.layout` refuses a graph with a blank or duplicate id, an edge to an
  unknown node or a step to an unknown node with `SceneError.InvalidGraph`, listing
  every problem; an ELK failure comes back as `SceneError.LayoutFailed` with its cause.
  Nothing is thrown.

### The look: drawn for print

Each shape says what it is part of (`Role`: a box, a container, a grouping, a mark such
as an icon, a patch of a field) and each line of text its `Weight` and `Emphasis`, and
the writers style by that, in the numbers `Look` holds so the PDF, SVG and PNG agree:

- a box in its layer's colour falling off a little from top to bottom, its edge a shade
  darker than its fill (the fill mixed half with the text colour), on a soft, short
  shadow to the lower right (`shadows.blur` in TikZ, a drop shadow in SVG, a blurred
  layer in PNG);
- a container a lighter field behind what it holds, its heading on a patch of that
  field so a line under it never runs through the letters; a grouping a dashed frame
  with its name on a tab;
- connectors 0.6 pt with rounded bends, `arrows.meta` heads sized per relationship
  (Stealth, open triangle, diamonds, barb, dot) and round dots for access; where one
  passes under another it is broken by a patch of the field the crossing lies on, and
  labels stand on such a patch too;
- drawn back to front: fields, boxes, lines, words, labels.

`Typeface` sets the face: what a standalone picture loads, how each weight is selected
in LaTeX, and the font files a box is measured with, found with `kpsewhich`, so a box is
measured in the very file LaTeX sets it from. `Typeface.heros` (TeX Gyre Heros) is the
default, `Typeface.montserrat` matches the Innovenso documents.

### The notation

Every element is a plinth with a sculpture on it. The plinth's form is the aspect (square
for structure, rounded for behaviour, chamfered for motivation), its colour the layer;
the sculpture is the element's icon, made solid; the name sits on a placard sloped
towards the viewer. A grouping is a glass tray with a dashed rim and its name on a tab.
Each plinth has four ports, one in the middle of each side.

### The layout

ELK Layered, top to bottom, which the scene reads as back to front. Each `ShapeGroup` is
an ELK partition: Motivation lies at the back, then Strategy, Business, Application,
Technology and Physical, with Implementation at the front. A first pass places the
plinths; a row wider than `Options.maxPerRow` (by default about the square root of the
graph) has its leaves folded into rows; the sides each connector meets on follow from
where its ends landed (one behind the other: south to north; side by side: east to west);
the last pass routes every connector orthogonally between the middles of those sides, and
the sides are chosen again from where the plinths ended up until they stop changing.
Where ELK leaves a connector between two containers unfinished, a small orthogonal router
takes it around the plinths; where the plinths leave no way through at all, the connector
gets a plain orthogonal route and `clear = false`.

The layout asks ELK (0.12.0) for model order, which makes the same graph give the same
scene. ELK fails on model order in some nested graphs, mostly larger ones; the layout then
runs without it. A nested graph whose connectors cross a container's edge can then come
out in one of a few ways from one run to the next, each keeping every rule above
(APP-2232). Layouts run one at a time: ELK's compaction shares state between layouts that
run at the same time, which would otherwise make the same graph differ.

### The scene

`Scene` is JSON through zio-json: per element its key, `type` (the builder's shape name,
`SceneNames.of`), name, centre `x`/`y`, footprint `w`/`d`, base height `z`, `parent` and
`container`, and its `pane` when it has one (above); per relationship its key, `type`, `sourcePort` and `targetPort`
(`north`, `south`, `east`, `west`; north is away from the viewer), `bends` and `clear`;
per flow its key, name and `steps`, each with `source`, `target`, `label` and the
`relationship` it runs along, when one joins its ends; and the scene's pane style as
`panes`. A scene without `flows` reads as one with none, one without `panes` with the
default style.

### In Blender

An element is one selectable object, its plinth; everything on it follows. A connector is
a curve hooked to its two ports, so it travels with both elements; an element standing on
a container is parented to it. `--check` moves an element and reports how far the
connector ends are from their ports. `--straight` ignores the layout's routes. Tested
headless on Blender 5.0.1 and 5.2.2.

A still renders with Cycles at 3840 by 2400 and 256 samples, denoised, unless `--size`
and `--samples` say otherwise; on the GPU when this Blender can render on one (OptiX,
CUDA, HIP, oneAPI or Metal), else on the CPU. The builder prints which, with the size and
samples.

A placard is small: in an overview of a large view its name renders a few pixels tall.
`--labels auto` (the default) then also floats each name above its element, about 16 px
tall in a render 1920 wide and as large a share of any other render, at any aspect, on a
light card. A floating name copies
the scene camera's rotation, so it stands upright in the render; it is parented to its
element and moves with it. The builder prints how tall a placard's name renders, and
`auto` floats the names when that is under 9 px in a render 1920 wide (the same share of
a larger one). Taken front to back, a floating name
that would cover one already placed moves up, at most eight times; the builder prints
how many names stayed covered and how many pairs still overlap, so a view too crowded
for its render size shows in the output. `--labels placard` and `--labels float` force
either.

### Passports: a glass pane beside the plinth

A leaf element can carry a `Passport`: what it is, told on a glass pane that stands next to
its plinth. The passport is generic: the scene does not know where the facts come from, so
a caller composes one per node from its own model, already in the reader's language.

```scala
import java.time.LocalDate

val crm = SceneNode(SceneId("crm"), NodeKind.Element(ApplicationComponent), "Customer Hub",
  passport = Some(Passport(
    eyebrow = "Application component",
    title = "Customer Hub",
    subtitle = Some("CRM · SaaS"),
    sections = List(
      PassportSection.Text("System of record for accounts, contacts and opportunities."),
      PassportSection.Facts(Some("Ownership"), List(Fact("Accountable", "Sales Operations"))),
      PassportSection.Timeline("Lifecycle",
        List(Milestone("Active", LocalDate.of(2021, 3, 15), Tone.Layer),
             Milestone("Deprecated", LocalDate.of(2028, 1, 1), Tone.Caution)),
        asOf = LocalDate.of(2026, 10, 13), summary = Some("Active since March 2021")),
      PassportSection.Rated("Criticality", Chip("High", Tone.Warning, Some("Sales cannot quote without it"))),
      PassportSection.Rating("Security", List(Mark("C", "H", Tone.Warning), Mark("I", "M", Tone.Caution))),
    ),
    footer = Some("as of 13 Oct 2026"),
  )))

SceneLayout.layout(graph, SceneLayout.Options(panes = PaneStyle()))
```

- The sections are `Text` (wrapped to the pane's width), `Facts` (label and value rows under
  an optional heading), `Rated` (one rating as a chip, with a note), `Rating` (a rating in
  letters, such as C·I·A) and `Timeline` (dated milestones on a bar, each colouring the
  stretch up to the next, with a mark at `asOf`). A `Tone` says what a chip, mark or stretch
  means (`Neutral`, `Layer`, `Good`, `Info`, `Caution`, `Warning`, `Critical`); the builder
  picks the colour, and `Layer` is the element's own layer colour.
- `PaneStyle(orientation, side, faceCamera, anchored, tint)` holds for the whole scene and
  is written into it as `panes`. `orientation` is `Auto` (the default), `Upright` (on a stem
  beside the plinth), `Lectern` (leaning back at the placard's 35°), `Flat` (on the floor)
  or `Floating` (above the sculpture, on a tether). `Auto` stands the panes upright while
  the camera is low and lays them flat once it looks down more than 56°. `side` is the side
  a pane prefers (`Right` by default); `faceCamera` keeps an upright or floating pane turned
  to the camera while it moves; `anchored = false` leaves out the stems and tethers; `tint`
  is `Clear` or `Layer`.
- The layout keeps floor free for each pane, so a pane stands on no other plinth, pane or
  connector: a leaf's ELK node grows by the pane's floor on its side, the plinth keeps its
  size, and its ports stay in line with the middle of its sides. A pane gives way to a
  connector: when one leaves its plinth on the pane's side, the pane takes the opposite
  side, then behind, then in front. `Auto` keeps room for flat, the larger of the two it may
  become; `Floating` takes no floor. Only a leaf element shows a pane, not a container, a
  grouping or a junction.
- `PaneLayout.height(passport)` is a pane's height, 2.1 units wide: the layout breaks text
  into lines by characters (`PaneLayout.lines`, greedy, never inside a word) at fixed sizes
  and line heights (`PaneLayout.metrics`). The builder lays a pane out with the same table,
  so the two agree without measuring text twice. In the scene each element with a pane
  carries `pane` with its `side`, `w`, `h` and `passport`; a section is written with its
  `kind` (`text`, `facts`, `rated`, `rating`, `timeline`).

In Blender a pane is a frosted glass slab (Principled BSDF, transmission) in a thin metal
rim, its passport in text objects, so a render is sharp at any size. It is parented to its
plinth and moves with it. An upright or floating pane turns to face the camera's azimuth;
a lectern or flat pane stays square to its plinth, on the floor the layout kept.
`--panes auto|upright|lectern|flat|floating|off` overrides the scene's style. A lectern or
flat pane lies over the bright floor, where clear glass lets the text fade into it, so it
is always frosted and tinted with its layer; the builder prints the glass it used.

The three.js shapes (`SceneBuilder.threeJs`) carry the pane too, for a preview in a
browser: `AM3D.pane(passport, opts)` builds one beside a plinth at the origin, placed as
the builder places it (`opts`: `orientation`, `side`, `layer`, `tint`, `azimuth`,
`anchored`, and `elevation` for `auto`), and `<canvas data-am="pane-application-component">`
shows an element with its pane (a sample passport, or the JSON in `data-passport`). The
face is painted on a canvas, as the placards are, laid out with the same table and line
breaking; `AM3D.paneHeight(passport)` equals `PaneLayout.height`, which `SceneThreeSpec`
checks by running the shapes in node (ignored without node). The builder
prints how many panes it built and how they stand, how far their heights are from the
layout's, how many lines came out wider than their room, and how many panes stand over a
plinth not their own. In an overview of a large view a pane is too small to read; it is
made for a close camera, a still of a few elements or a flyover.

### Pointing: highlight and flyover

`--highlight` puts what it names in the light and dims the rest: a spot falls on each
element, and a connector glows in amber with a softer spot on both its ends. It takes
a comma-separated list; each item is a key, an element's name (any case) or
`source>target` (names or keys) for the connectors between two elements, either way
round. Each thing is lit once, however often it is named. The builder prints how many
elements and connectors it lit, how many spots hang and how far the ambient light is
turned down, and each item that named nothing.

```bash
blender -b -P archimate3d_blender.py -- --view scene.json \
  --highlight "Order System,Customer>Handle Order" --render lit.png
```

`--flyover` takes a flow by key or name (the first flow without one) and writes a camera
flight through it into the `.blend` timeline. The overview comes first, in full light;
then, per step, the camera glides to the step's two elements and looks at them from the
side, both lit while the rest dims, while a pulse runs from source to target and leaves
an amber trail: along the connector that joins them, on the route it was drawn on
(`--straight` included), or in an arc above the scene where none does. A step from an
element to itself runs once round a ring standing on its plinth, turned to face the
camera. A shot holds at least five units of floor (a leaf's plinth is two units wide), so
a near pair or a single element is not seen from too close. The step's number and label
stand in a caption bar at the top of the frame, its height a fixed share of the frame's;
a label longer than 60 characters is cut short. A finished step's trail thins and stops
glowing, so the flow so far stays visible; at the end the camera returns to the overview
and the light comes back. A step takes about 3.3 seconds. Floating labels stay off: the
camera comes close enough for the placards.

Passports ride along. A step lights the panes of its two elements with a soft light held
by each pane, so a lit pane reads while the rest dims (a `--highlight` does the same for
the elements it names), and its shot frames those panes with the plinths. After a step,
each of its elements whose pane was not read yet gets a passport moment: the camera
glides square on to the pane and frames it, holds 3.2 seconds, and flies on. The pane
fills the frame bar a margin of a tenth on each side, along whichever side binds: a tall
pane fills the height, a wide and low one (a passport with little to say) the width. A
pane that turns to the camera (`faceCamera`) is read from the side the camera comes
from, a little above; a lectern or flat pane along its face. Each pane is read once a flight, and a flow without passports
flies as it did. The builder prints how many moments it made, how far inside the frame
the panes of each step stay, the smallest share of the frame a pane fills while it is
read, along the side that binds (about 0.8; much less means a read did not frame its
pane), and how many moments showed their pane upside down.

The builder measures the flight it made and prints it: how many steps ran along a
connector, how far inside the frame both plinths of every step stay (at its arrival,
mid-run and departure), with its route, how far below the caption bar, how far each route
strays from its connector (an arrowhead's length, since a route ends on the ports), the
largest share of the frame's width a leaf's plinth takes (how close the camera comes),
and how wide a step to itself opens its ring. A flow it cannot find, by key or name, is
reported, and `--animation` then writes nothing.

`--animation out.mp4` renders that timeline to an H.264 video with EEVEE (64 samples,
raytracing on, so a pane's glass refracts as it does in Cycles) and Blender's
own encoder (no ffmpeg needed), at 1920 by 1080 unless `--size` says otherwise and 30
frames a second unless `--fps` does. `--frame N --render still.png` renders one frame of
the flight as a still, with Cycles; useful for a thumbnail or to check the camera.
A video takes time: about 0.6 seconds a frame at 1920 by 1080, measured on an RTX
3090, so a flight of a minute (1800 frames) renders in about twenty minutes, and much
longer on a CPU. Highlight, flyover and animation are tested headless on Blender 5.0.1
and 5.2.2; the animation needs a Blender that can run EEVEE without a display, as 5.x
does.

```bash
blender -b -P archimate3d_blender.py -- --view scene.json \
  --flyover "Place an order" --blend flight.blend --animation flight.mp4
```


## Diagrams: ArchiMate drawn flat

`genius-uml-diagram` draws a `SceneGraph` as a flat ArchiMate diagram without PlantUML.
It lays the graph out with the same ELK pass as the 3D scene, so the diagram in a
document and the scene in a flyover show the same landscape in the same places, and
draws it as plain geometry that three writers put out:

| Writer | Output | Needs |
|---|---|---|
| `Tikz.picture(drawing, palette)` | a `tikzpicture` in absolute centimetres | TikZ with `arrows.meta` (`Tikz.libraries`) |
| `Tikz.standalone(drawing, palette)` | a `standalone` document around it, set in TeX Gyre Heros | pdflatex |
| `Svg.document(drawing, palette)` | an SVG document | nothing |
| `Png.image(drawing, dpi, palette)` | a PNG, drawn with Java2D | nothing |

```scala
import fish.genius.uml.diagram.*

Diagram.draw(graph).map: drawing =>
  os.write.over(os.pwd / "landscape.tex", Tikz.standalone(drawing))
  os.write.over(os.pwd / "landscape.svg", Svg.document(drawing))
  os.write.over(os.pwd / "landscape.png", Png.image(drawing))
```

### What a box says

A box says its node's `label`, then its `caption` (the type and technology, smaller),
then its `note` (a line or two about it, smaller still), then its badges (below). A
connector says its edge's `label`. These are optional fields of `SceneNode` and
`SceneEdge`; the 3D scene
leaves them out. Every line is placed by `Diagram` on its baseline, so the PDF, SVG and
PNG set the same text in the same place.

Boxes are sized to what they say, measured in the diagram's font (the first of
`Style.fontFamilies` that is installed: TeX Gyre Heros, Nimbus Sans, Liberation Sans,
all with Helvetica's metrics). A box is 3 cm wide, 3.8 cm when it has a note or its name
would take more than two lines, wider still for a word that does not fit; as tall as
its lines need. The name and caption keep clear of the icon on both sides, so they stay
centred. `Drawing.overflow` counts the lines wider than their room. The same graph gives
the same drawing on one machine; on a machine with other fonts installed the boxes can
differ by the width of a letter, since they are measured in the first family it has.

A container's name and caption stand in a header strip at its top. ELK sizes a
container from its children, so a long name may not fit beside the icon; it then breaks
over as many lines as it needs, and the layout runs again with every header that much
taller.

### Badges, a fill of its own, and the legend

A leaf may carry `badges`: small signs at its foot, in a row centred under what it says,
drawn solid in its box's mark colour (`Badge(glyph, label)`). `Glyph` has twelve
geometric glyphs to tell things apart (circle, square, triangles up and down, diamond,
star, hexagon, cross, pentagon, ring, ellipse, chevron), and four with a meaning: a globe
and a padlock for a public and a closed API, a warning and a failure for a degraded and
a failing health. The box grows by a row when its lines leave no room, and wide enough
for the row.

A node's `fill` (six hex digits, `#` allowed) sets it apart from its layer: the box is
drawn in that colour as in a layer of its own (edge, fall-off and icon mixed from it).
The colour travels in `Drawing.colours`, as `am-fill-<hex>`, and every writer defines it.
A fill that is not a colour is ignored.

`SceneGraph.legend` (`Legend(title, entries, sections)`) says what the diagram's marks
stand for. It is drawn under the diagram, left-aligned with it, in a framed box: the
title, then the badges (`entries`), then each `LegendSection` under its heading. A
section's items (`LegendItem`) are a badge (`Mark`), an element type (`Shape`: a small
box in its layer's colour with the type's icon), a relationship (`Line`: a short line
with that relationship's dash and ends) or a logo (`LogoMark`), each with its text.
Each group's items stand in as many columns as fit the drawing's width, every mark
centred in a column as wide as the widest of its group. Empty sections are left out,
and a legend with nothing in it draws none. The 3D scene leaves badges, fill and legend
out.

### Logos

A `Logo` is a vector logo (`Logo.Vector(minX, minY, width, height, shapes)`: filled
outlines in SVG path syntax, in the coordinates of its own view box, each `LogoShape` in
its colour and optionally cut by the even-odd rule) or a picture (`Logo.Picture(data,
mime, width, height)`: a PNG or JPEG, base64). `Logos.fromSvg(svg)` reads one from an
SVG document: its paths, rectangles, circles, ellipses, polygons and polylines, filled
as the document (or the group round them) says, through the translate, scale, rotate
and matrix transforms of groups and shapes. It fills, it does not stroke: an outline
icon drawn with strokes comes out as solid shapes. A fill it cannot read as a colour
(`currentColor`, a gradient, an unknown name) is black; opacity, `display`, clip paths,
masks and text are not drawn. A document with a DTD is refused, so no entity reaches
outside it, as is one over 4 MB or with groups nested deeper than 64. `Logos.fromPicture(bytes, mime)`
reads a picture and its size from its header: only a PNG or a JPEG (by what it is, not
what it is called), of at most 16 million pixels. A logo built directly is drawn only
in six-digit colours and with base64 picture data, so nothing else reaches a writer.

A `Badge` with a logo is drawn as that logo, 1.4 times the glyph's height and up to
three times as wide as high, in its own colours; without one it keeps its glyph. The
legend shows each entry's logo or glyph, centred in a column as wide as the widest. A
leaf node with a `logo` shows it in its top left corner, as high as the icon in the
opposite corner and up to three times as wide, and the name keeps as clear of it as of
the icon. A container shows no logo.

A logo is drawn as `Prim.Curve` (moves, lines and cubic curves; `SvgPath.parse` reads M,
L, H, V, C, S, Q, T, A and Z, absolute and relative, a quadratic or an arc becoming
cubics) and `Prim.Image`. The SVG writer writes a path and an embedded image, the PNG
writer Java2D's paths and the decoded picture. The TikZ picture draws curves with
controls and includes a picture as a file: `Tikz.files(drawing)` names each file the
picture includes and gives its bytes, for the caller to write next to the `.tex` it
compiles.

### The notation

ArchiMate 3.2's box notation: a square box for structure, rounded corners for behaviour
and strategy, cut corners for motivation, and a band across the top for a passive object
(data object, business object, contract, representation, artifact, material). Every
element type has its icon in the top right corner (`Notation.icon`, a total match over
`ShapeType`); a grouping is a dashed frame, a junction a dot. Every relationship type has
its line and ends (`Notation.ends`): a filled diamond for composition, an open one for
aggregation, a dot and arrow for assignment, a dashed line with an open triangle for
realization, an open arrowhead for serving, a dotted line for access (the arrowhead
pointing the way the data goes), and so on.

The layer colours are named `am-business`, `am-application`, `am-technology`,
`am-physical`, `am-strategy`, `am-motivation`, `am-implementation`, with `am-line` for
the lines and text. `Notation.palette` holds ArchiMate's suggested fills. The TikZ
picture *provides* them, so a document that defines `am-application` before it keeps its
own; a `palette` passed to a writer replaces them outright. A palette entry counts only
with a name of lower-case letters, digits and dashes and six hex digits (`#` allowed);
any other entry is left out. Text is escaped for LaTeX and XML, and control characters
become spaces.

### The layout

`Diagram` calls `SceneLayout.layout` with four options the 3D scene leaves off. With them
off the scene is exactly what 1.9.1 made (`SceneGoldenSpec` holds a nested scene to it):

- `footprint`: each leaf's size, from what its box says.
- `headerAtBack`: a container's header at its top, where a diagram is read first.
- `spreadPorts`: each connector gets its own port, which ELK places along the side, so
  connectors meeting a box on one side do not run on top of one another.
  `SceneRelationship.start` and `end` carry where it leaves and arrives. It keeps no
  floor for a passport's pane, so a graph with passports leaves it off. With it, an
  edge running up against the layers is handed to ELK the other way round (and its
  route turned back after), and a container's ports are free, so an edge crossing a
  container's edge enters on the side that faces it instead of looping round.

After the layout `Diagram` tidies the routes: a tiny step ELK leaves where two
stretches nearly line up is straightened (an end slides that little along its box's
side), and stretches of different routes that lie on top of one another are spread
apart, in the order they part.
- `compact`: nodes placed with network simplex and the result compacted; where ELK
  cannot (it fails on some nested graphs) the layout falls back to the plain one.
- `rowWidth`: a row of one parent wider than this (a page, `Diagram.Options.pageWidth`,
  13 cm) folds, so the diagram prints at its own size rather than scaled down.
- `labelSize`: how large a connector's label is, so ELK keeps room for it.
  `SceneRelationship.label` carries where it went. ELK places the label of a connector
  that crosses a container's edge in another frame; when the room it kept is off the
  route, `Diagram` puts the label on the route's longest stretch instead, where it covers
  no box and no header.

### Sequences: messages between parts

`Sequence.draw(graph, options)` draws a sequence of messages in the same look, so a
document that draws its landscapes with `Diagram` sets its sequence diagrams in one
style with them. It returns a `Diagram.Drawing`, and the same three writers put it out.

```scala
import fish.genius.uml.diagram.*
import fish.genius.uml.diagram.Sequence.*
import fish.genius.uml.dsl.archimate.ShapeType

val shop = Some(Group("Web Shop", Some(ShapeType.ApplicationComponent)))
val drawing = Sequence.draw(
  Graph(
    "Checkout",
    List(
      Lifeline("customer", "Customer", ShapeType.BusinessActor, Some("Business Actor")),
      Lifeline("api", "Order API", ShapeType.ApplicationComponent, Some("[Container: Scala]"), shop),
      Lifeline("db", "Order Store", ShapeType.ApplicationComponent, None, shop),
    ),
    List(
      Step.Send("customer", "api", "Place the order", Kind.Call, Some("HTTPS {Order}")),
      Step.Loop("until stored", List(Step.Send("api", "db", "Store it"))),
      Step.Send("api", "customer", "Order confirmed", Kind.Reply),
    ),
  )
)
os.write.over(os.pwd / "checkout.tex", Tikz.standalone(drawing))
```

- **A part** (`Lifeline`) has a head at the top: a box in its shape's layer colour with
  its icon in the corner, its name and its caption centred, and a fine dashed lifeline
  under it in the box's edge colour. The parts of one `Group` that stand side by side
  share a field (a container of the group's shape, or a dashed grouping without one)
  with the group's name in its header.
- **A message** (`Step.Send`) is a horizontal line from one lifeline to another, its
  number and its label above it, and `detail` (technology, payload) under the label in
  a quieter italic. A `Call` ends in a filled arrowhead, a `Reply` is dashed with an open
  one, a `Signal` is solid with an open one. A message to itself turns back on its own
  lifeline. A message to an id that is not a part is left out. `Options.numbered`
  (on by default) numbers them in order.
- **A loop** (`Step.Loop`) is a frame round its messages, with a tag saying *loop* and
  its condition beside it; a frame inside another sits a little further in. A loop with
  no message in it is left out.

The columns stand as close as the heads allow, then as far apart as each label needs
(the shortest spans first, so a long message only widens what the short ones between
its ends did not). A label keeps off the edge of a field it crosses: it stands on the
longest stretch between the edges, which is widened until it fits. A label wraps at
`Options.labelWidth` or as wide as its stretch already is, whichever is wider, narrowed
until the diagram keeps within `Options.pageWidth`. A lifeline is broken where a word
stands on it, so a label reads clean without a patch behind it.

### Activities: a process with swimlanes

`Activity.draw(graph, options)` draws a process as an activity diagram with swimlanes,
in the same look, so a document sets its processes in one style with its views. It
returns a `Diagram.Drawing` for the same three writers. It draws BPMN's Analytic
conformance level: every event trigger caught and thrown, boundary events, expanded
sub-processes, transactions and event sub-processes, task markers, data, messages
between pools and compensation associations. Groups are not drawn.

```scala
import fish.genius.uml.diagram.*
import fish.genius.uml.diagram.Activity.*
import fish.genius.uml.dsl.archimate.ShapeType

val drawing = Activity.draw(
  Graph(
    "Handle an order",
    List(Lane("sales", "Sales desk", Some(ShapeType.BusinessRole))),
    List(
      Node("start", "Order placed", Kind.Start(Trigger.Message), Some("sales")),
      Node("check", "Check the order", Kind.Work(Task.User), Some("sales"), Some("[CRM]")),
      Node("ok", "Complete?", Kind.Gateway(Gate.Exclusive), Some("sales")),
      Node("done", "Order accepted", Kind.End(Trigger.Plain), Some("sales")),
    ),
    List(
      Flow("start", "check"),
      Flow("check", "ok"),
      Flow("ok", "done", Some("yes")),
      Flow("ok", "check", Some("no"), default = true),
    ),
  )
)
```

- **Lanes** are columns, the flow runs from top to bottom. Each lane is a light field
  with its name in a header, and the icon of its performer's `shape` beside it. A node
  in no lane (or in a lane not listed) stands in a column of its own after them; a
  graph without lanes has one column and no header.
- **A task** (`Kind.Work`) is a rounded box in the business colour with its name, the
  `detail` (the systems that support it) under it in a quieter voice, and an icon for
  its kind (`User` an actor, `Service` a component, `Script` an artifact, `Rule` a
  principle, `Call` a process, `Send` a filled envelope, `Receive` an open one; `Manual`
  and `Plain` have none); a collapsed `Sub` process has a small plus at the bottom.
  `markers` stand at its foot beside the plus: `Loop`, `Parallel` and `Sequential`
  multi-instance, `Compensation`, `AdHoc`.
- **An event** is a circle with its trigger inside and its name beside it: thin at the
  `Start`, double for an `Intermediate` one, thick at the `End`. Every BPMN trigger is
  drawn (`Message`, `Timer`, `Error`, `Escalation`, `Cancel`, `Compensation`,
  `Conditional`, `Link`, `Signal`, `Terminate`, `Multiple`, `ParallelMultiple`), open
  where the event catches it and filled where it throws it (an intermediate event
  with `throwing = true`, and every end). A start with `interrupting = false` (an
  event sub-process's) is dashed.
- **A boundary event** (`Kind.Boundary`, with the node it sits on as `host`) is a
  double circle on its host's bottom edge, dashed when it does not interrupt, its name
  beside it below the host; its flows leave from below. It takes its host's row, so
  what it leads to is placed under the host, and a task with many events on its edge
  grows to fit them side by side. One whose host is missing is drawn as a node.
- **A gateway** is a diamond with its kind inside (X exclusive, + parallel, O
  inclusive, event-based, an asterisk complex, a + in a circle parallel event-based),
  its question above its right side.
- **A container** (`Kind.Container`) holds the nodes whose `parent` it is: a `Sub`
  process with a solid frame, a `Transaction` with a double one, an `Event`
  sub-process with a dotted one. What it holds is laid out on its own (no lanes, in
  the container's lane) and the container takes its place in the flow as one block,
  its name at the top left; containers nest. An event sub-process no flow reaches
  stands under everything else. A container that holds nothing is drawn collapsed,
  as a task with the plus. A `parent` that is not a container here, or a chain of
  parents that comes back round, counts as none. A flow between a node inside a
  container and one outside it is not drawn (BPMN does not allow one); a message to or
  from a node inside meets the outermost frame drawn. A container is as wide as what it
  holds needs, and is not narrowed to the page.
- **Data** (`Node.data`, a `Datum`) stand in a column beside their task: a page with a
  folded corner, or a cylinder for a `store`, with its name beside it, tied to the
  task by a dotted line with its head at the task when the task reads it and at the
  data when it writes it (`output`). A container's data are not drawn.
- **A message** (`Graph.messages`) runs between pools: a dashed line from an open
  circle to an open head, across from the side of its source that faces its target,
  its name over the middle. Either end may be a lane without nodes, which is a pool
  drawn as a black box: a narrow column the message meets at its near edge.
- **An association** (`Graph.associations`), from a compensation boundary event to the
  task that compensates it, is a dotted line with a head; the task is placed under
  the event's host.
- **A flow** is a fine line with an arrowhead. A branch leaves a gateway from the
  corner that faces its target, with its `label` (the condition) there; a flow into a
  gateway that others join comes in at the corner that faces it; a `default` flow has
  a short stroke across its start. `notes` stand beside their node in a bracket.

The layout is layered. The flows that close a loop (found by a walk from the starts,
following flows in their order) are set aside; every node is placed on the row its
longest path from a start gives it, and in its lane on a track of its own when its row
holds more than one node there, ordered under the nodes it comes from. A flow goes
straight down when it can, else down, across in the gap above its target (or below its
source) and down again, else round the right of what is in the way; a loop goes back
up round the right of everything it passes and into the right of its target. Where
two flows cross, the one across is broken, as in `Diagram`. The walk and the ranking
recurse once per node of a chain, which suits a process of dossier size (hundreds of
steps), not one of tens of thousands. Tasks wrap narrower
(`Options.taskWidth`, then 2.4 and 2.0 cm) until the diagram keeps within
`Options.pageWidth`.
